# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите правообладателю на
letenkovmaksim@yandex.ru (тема — `stvor-agent security`) или используйте GitHub Security
Advisories этого репозитория («Report a vulnerability»). Укажите версию (`stvor-agent version`; для
3.x — `bisquite-teleport version`), шаги воспроизведения и что именно удаётся сделать. Ответ — в течение
7 дней.

Поддерживаются последняя выпущенная версия 4.x и `bisquite-teleport-agent` 3.1.x — пока портал Stvor
пинит 3.x (до его перехода на 4.x). Исправления выходят новым патч-релизом с `SHA256SUMS`.

## Модель угроз

Что защищаем: доступ к машине через Teleport (метки `env`/`space` решают, кто и куда может войти) и токен
меток, которым машина представляется порталу. Кому доверяем: root на машине, cream и расширение
`teleport` (ставятся по пину sha256), портал по `url=` из файла токена — в пределах двух значений меток.
Кому не доверяем: сети между машиной и порталом сверх TLS, телу ответа портала, непривилегированным
пользователям машины.

### Служба работает от root

`stvor-agent.service` запускается от root: дочерний `cream run teleport set-managed` пишет
`/etc/cream/teleport/config` и перезапускает `teleport.service`. Поверхность недоверенного ввода — ответ
портала ≤ 4096 байт:

- только `https`, TLS ≥ 1.2, системные корни; редиректам служба не следует (3xx — неудача тика);
  соединение 10 с, весь запрос 30 с;
- тело `200` разбирается по токенам `encoding/json` (не `Unmarshal`): ровно
  `{"labels":{"env":S,"space":S},"revision":S}`, ключи по порядку и по одному разу, без хвоста, валидный
  UTF-8, без NUL и экранирований; `env`, `space` — `^[a-z0-9][a-z0-9-]{0,62}$`, `revision` —
  `^[0-9a-f]{16}$`. Иначе — `bad_body`, ничего не тронуто ([контракт](docs/reference/portal-labels-api.md));
- в `teleport` уходят ровно два ключа `env` и `space`, аргументами `exec` без shell. Портал не может
  через агента поменять кластер, регистрацию, приложения и прочие метки и не может доставить код.

Портал при этом — корень доверия для доступа: сменив `space`/`env`, он переносит машину между
пространствами, и роли кластера дают доступ по новым меткам.

### Токен меток

- 43 знака `[A-Za-z0-9_-]`; принимается только со stdin `stvor-agent enable` (одна строка, пробелы по
  краям срезаются; ошибки ввода не цитируют его).
- Хранится в `/etc/stvor-agent/token` (`url=`, `token=`): файл 0600, владелец root, каталог 0700,
  запись атомарная (временный файл → `fsync` → `rename` → `fsync` каталога). Другие права, владелец или
  формат — отказ с причиной; токен не отправляется.
- Файлы токена и `state.json` открываются с `O_NOFOLLOW` (символическая ссылка — отказ) и
  `O_NONBLOCK` (FIFO не вешает службу).
- Токен уходит только в заголовок `Authorization` на `url=` из того же файла; адрес — строго
  `^https://[a-z0-9.-]+(:[0-9]{1,5})?/robot-api/v1/labels$`. Никогда — в argv, окружение дочерних
  процессов, журнал, `status`, `state.json`, текст ошибок.
- `stvor-agent version --label` (её исполняет Teleport) только проверяет существование файла (`stat`),
  не читая его.

### Окружение дочерних процессов

`cream` вызывается абсолютным путём `/usr/bin/cream`, без shell, с окружением ровно
`PATH=/usr/sbin:/usr/bin:/sbin:/bin` и `LANG=C.UTF-8` (ни токена, ни прокси, ни переменных службы),
stdin — `/dev/null`, в своей группе процессов; вывод `managed-status`/`set-managed` ≤ 64 КиБ разбирается
строго (схема 1). По тайм-ауту группа получает SIGTERM, через 15 с — SIGKILL.

Секрет регистрации Teleport агент не видит никогда: он идёт только в `cream run teleport join` со stdin.

### Hardening юнита

`NoNewPrivileges=yes`, `PrivateTmp=yes`, `ProtectHome=yes`, `ProtectKernelTunables=yes`,
`ProtectKernelModules=yes`, `ProtectKernelLogs=yes`, `ProtectControlGroups=yes`, `ProtectClock=yes`,
`ProtectHostname=yes`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, `RestrictNamespaces=yes`,
`RestrictRealtime=yes`, `RestrictSUIDSGID=yes`, `LockPersonality=yes`, `MemoryDenyWriteExecute=yes`,
`SystemCallArchitectures=native`, `UMask=0077`. Строки сверяет тест `packaging/unit_test.go`.

**Почему без `ProtectSystem=`.** Ограничения юнита наследуют дочерние `cream` и расширение `teleport`, а
они пишут `/etc/cream/teleport`, `/etc/teleport.yaml` и `/var/lib/cream/ext/teleport`. Перечислить эти
пути в `ReadWritePaths=` — связать юнит агента с раскладкой чужого расширения: любое её изменение молча
ломало бы применение меток. Сам агент Teleport запускает systemd в своём юните — ограничения агента на
него не распространяются.

Агент не открывает портов (ни метрик, ни API): с людьми он общается только CLI и журналом.

### Цепочка поставки

- Только стандартная библиотека Go; `make vuln` — govulncheck по модулю.
- Воспроизводимая сборка: `CGO_ENABLED=0 -trimpath -buildid=`, nfpm по пину, `SOURCE_DATE_EPOCH`;
  `make repro-check` в `make ci` — две сборки с пустыми кешами дают равные sha256 `.deb`.
- Релиз несёт `SHA256SUMS`; обёртка каталога cream-extensions и зеркало портала ставят пакет по пину
  версии и суммы архитектуры, сверка `sha256` — до `dpkg -i`. Подписи релизов пока нет.

## 3.1.1: версия кластера в арифметике bash

Касается только `bisquite-teleport-agent` ≤ 3.1.0 (bash); в 4.x этого кода нет — регистрация живёт в
расширении `teleport`, куда исправление перенесено. CVE не заведён.

**Суть.** При `join` агент 3.x спрашивал прокси `/webapi/find` и сравнивал `server_version` с версией
бинаря внутри арифметики bash `(( ))`. Bash вычисляет индекс массива в арифметическом выражении,
поэтому значение вида `a[$(команда)]` выполняло команду от root. Подставить такое значение мог прокси
(или тот, кто встал между машиной и прокси до проверки CA).

**Исправление (3.1.1).** `server_version` проверяется сразу после ответа: только
`X.Y.Z[-pre][+build]` с компонентами до 9 цифр, дальше используется `X.Y.Z`; иное — код 101 «прокси
назвал версию не по форме», `join` ждёт, повтор — тиком `join-retry`. Сравнение версий сверяет обе с
регулярным выражением до `(( ))` и считает в базе 10. Числовые переменные окружения и значения из
`passwd`, `stat` и файлов состояния тоже проверяются как целые до арифметики.

Обновитесь до 3.1.1 или перейдите на 4.x.
