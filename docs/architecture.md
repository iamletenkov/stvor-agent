# Как устроен агент

Решения и их причины — [спека](specs/2026-10-18-stvor-agent-go.md); модель угроз —
[SECURITY.md](../SECURITY.md).

## Место в системе

```
портал Stvor ──GET /robot-api/v1/labels──► stvor-agent ──cream run teleport set-managed──► teleport.service
     ▲                                          │
     └──────── X-Applied-Revision ──────────────┘
```

- **Портал** решает, какие `env` и `space` у машины, и отдаёт их по
  [контракту](reference/portal-labels-api.md).
- **stvor-agent** забирает метки и добивается, чтобы они действовали.
- **Расширение `teleport`** каталога cream владеет регистрацией узла, `teleport.yaml`, приложениями и
  управляемыми метками; агент говорит с ним только через `cream run teleport managed-status|set-managed`.
- **Обёртка `stvor-agent`** каталога ставит пакет по пину и включает метку `stvor_agent`.

## Один опрос

1. Взять блокировку `/run/stvor-agent.lock` (служба — без ожидания; занята — опрос пропускается).
2. Прочитать токен и `state.json`; запросить портал с `If-None-Match` по запомненной ревизии.
3. Ответ `200` разобрать строго, запомнить; `304` — взять запомненный.
4. Спросить у `teleport` фактические управляемые метки (`managed-status`).
5. Если они расходятся с порталом или перезапуск не подтверждён — `set-managed env=… space=…`: запись
   меток и один перезапуск `teleport.service` с подтверждением.
6. Записать `state.json`; ревизию, которая действительно действует, отправить порталу на следующем
   опросе в `X-Applied-Revision`.

Сверяется состояние, а не ревизия: шаги 4–5 выполняются на каждом опросе, в том числе при `304`.

## Расписание

- Первый опрос — через случайные 0–20 с после старта, дальше — `интервал + U[0, 20 с)`; интервал —
  `STVOR_AGENT_INTERVAL` (60–600 с).
- Неудача (сеть, TLS, тайм-аут, 3xx, 429, 5xx, тело не по контракту) — backoff
  `min(интервал · 2^min(n,3), 600 с)`; `200`/`304` сбрасывают счётчик; `401` — пауза 600 с, которую
  прерывает только `enable`.
- После трёх неподтверждённых перезапусков подряд при активном агенте Teleport — не чаще раза в 15 минут;
  `sync` и `apply` этой паузой не ограничены.
- `SIGHUP` — опрос сейчас; `SIGTERM` — дождаться конца опроса и выйти.

## Пакеты Go

| Пакет | Что делает |
|---|---|
| `cmd/stvor-agent` | точка входа |
| `internal/cli` | команды, `KEY=VALUE`, коды выхода, `status`, man-страница |
| `internal/daemon` | цикл службы: джиттер, backoff, сигналы, блокировка, настройки из окружения |
| `internal/reconcile` | один опрос: сверка ожидаемого с фактическим, политика перезапусков |
| `internal/portal` | клиент `/robot-api/v1/labels`: запрос, строгий разбор тела, классификация ответа |
| `internal/teleport` | адаптер `cream run teleport …` и разбор его JSON |
| `internal/token`, `internal/state`, `internal/atomicfile` | файл токена, `state.json`, атомарная запись и чтение без ссылок |
| `internal/platform` | семейство машины по `os-release` (Debian/Ubuntu или OpenWrt): пути, имя расширения `teleport` |
| `internal/initsys`, `internal/version` | init-система: `systemctl` или procd (`/etc/init.d/<служба>`), версия из сборки |

Только стандартная библиотека Go. Внешнее — файлы, `systemctl`/procd, `cream`, портал, часы — подменяется
интерфейсами в тестах.
